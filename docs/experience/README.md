# Experience Notes

`docs/experience/` stores reusable project lessons extracted from plans, logs,
commits, reviews, validation reports, and failed attempts. It is not a second
maintenance log.

Experience notes are written in English so terminology, paths, commands, and
cross-target guidance remain consistent. Source evidence may use another
language, but the extracted lesson is normalized to English.

## What Counts as Experience

A note explains a transferable judgment: the tested assumption, observed
outcome, supporting evidence, resulting rule or habit, and its limits.

Raw file lists, copied commit messages, daily status, and uninterpreted
validation transcripts belong in Git history.

## Human and Agent Responsibilities

Experience extraction is human-triggered. A human decides whether evidence is
worth turning into a reusable lesson. When asked, an Agent may surface signals,
draft a candidate with citations, and fill the template; the human accepts,
edits, or rejects it.

## Suggested Workflow

1. Let commits record the facts first.
2. A human reviews recent work and requests extraction when warranted.
3. The Agent drafts a candidate citing plans, logs, commits, or reports.
4. The human accepts, edits, or rejects it.
5. Mature lessons may feed back into `AGENTS.md`, templates, or checks.

Use dated names for event-specific lessons and stable names for evergreen
practices. Start from `lesson.template.md`.
