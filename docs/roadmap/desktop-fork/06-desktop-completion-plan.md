# 离线桌面版完善方案：项目管理与共享机制

日期：2026-10-11。状态：实现和本地验收进行中；未发布新桌面包。

本方案承接 [#1119](https://github.com/cascode-ai/analog-canvas/issues/1119)、
[#1121](https://github.com/cascode-ai/analog-canvas/issues/1121) 与
[首轮迁入计划](05-local-merge-plan.md)。本轮结束时交付一版可独立日常使用的
Windows 离线绘图软件：项目可以管理、保存、复制、恢复和迁移，核心编辑机制
跟随线上主线，实际发布包经过完整断网验收。

“同步线上”指共享模型、操作含义和适用的实现；用户数据始终留在本机。
账号、Cloud、Gallery、云端共享元件、拓扑查重服务、统计、模拟、Agent/MCP
不进入离线版。内置元件、项目内嵌元件及源数据属于项目内容，必须完整保留。

本文是实施计划，不把未来目标写成现有行为。实施对应目标时同步更新
[持久化契约](../../specs/persistence-and-recovery.md)、
[文件协议](../../specs/project-file-format.md)中实际受到影响的规则及
[持久化 ADR](../../adr/persistence.md)。其他主线契约继续有效。

## 2. 本地项目库和数据归属

首次启动建立可写的默认项目库，例如 `%USERPROFILE%\Analog Canvas\Projects`，
在界面持续提供实际路径和“打开所在文件夹”。路径按当前用户解析，不硬编码账号；
默认避开程序目录、临时目录和自动选取的云同步目录。用户可以选其他本地目录。
初始化失败时提示原因并提供更换目录；编辑及恢复仍可用，不能虚报已保存。
本应用不执行同步；用户或第三方软件选择同步某目录的行为不由离线声明保证。

- 每个入库项目有稳定的管理标识和独立目录，其中保留标准 `.icproj.json` 文件。
  管理标识与项目内部身份、外部文件路径分别处理，不靠项目标题决定身份。
  改标题不隐式移动文件；同名项目可以并存并显示位置以区分。
- 项目文件是内容依据，列表索引可由目录重新扫描建立。收藏等管理元数据另存，
  索引损坏不能丢失或覆盖项目；项目目录复制到另一台机器后可发现并打开。
- 更换默认项目库只改变新项目的目的地，已有库保留可访问入口；不静默搬移作品。
  需要迁移时先关闭写入，复制并验证可打开后切换位置，原目录由用户另行处理。
- 外部文件可以原位打开、保存，并进入最近列表；“复制到项目库”显式创建独立副本，
  不移动源文件。只读、移动、删除或外部修改均给出可恢复操作。
- 普通关闭、重启、程序包替换和清理缓存均不得删除正式项目。

| 数据                         | 生命周期                                               |
| ---------------------------- | ------------------------------------------------------ |
| 程序与内置资源               | 随程序包替换，和用户作品分离                           |
| 正式项目与管理元数据         | 项目库/用户选择的位置；支持备份和迁移                  |
| 项目保存历史                 | 当前版本加最近三个先前版本；随项目管理，不属于缓存     |
| 设置、索引、最近记录、工作区 | 稳定用户数据目录；与具体程序版本目录分离               |
| 未保存内容与崩溃恢复         | 独立恢复存储；不得被“清理缓存”一并清除                 |
| 临时文件、渲染缓存、日志     | 有容量或保留期，可安全清理；日志不记录项目正文和秘密值 |

## 3. 保存、独立副本与导出

| 操作          | 完成后的用户可见结果                                                                         |
| ------------- | -------------------------------------------------------------------------------------------- |
| 新建          | 生成未保存工作副本；编辑时持续保留恢复数据，空白草稿关闭可直接丢弃                           |
| 保存 / Ctrl+S | 更新当前正式项目；未绑定的新项目首次保存自动分配项目库目标，无需选路径或先导出               |
| 另存为        | 以当前编辑内容创建独立项目、新项目身份与存储绑定；成功后切换到新项目，原项目最后保存内容不变 |
| 列表“复制”    | 复制选定项目的已保存内容，使用同一个独立副本规则；不悄悄替代当前编辑页                       |
| 导出项目文件  | 生成标准交换副本，保留内容身份，不改变当前保存绑定或清除其未保存状态                         |
| 重命名        | 修改项目标题并经同一保存规则持久化；保留身份和历史，不隐式改外部文件名                       |

另存为默认选择本地项目库，可更改名称或目的地；保存到其他位置后，后续 Save
写该位置。不能以另存为覆盖当前源项目来冒充独立副本；选择正在其他标签中打开
的目标必须拒绝。覆盖其他已存在文件需要明确确认，失败保持原文件和原绑定。确认覆盖前
必须保留目标旧项目及其历史为可恢复记录；新项目建立新的历史归属，不能把同一路径
之前的另一项目版本混入新项目历史。若无法完整保留旧目标，则拒绝覆盖并要求选择新位置。

与线上对齐的是“更新当前资源”和“创建独立副本”的行为，不强制两端菜单完全相同。
线上列表 Duplicate 已创建新 Project 身份；已有内部 `asNew` 保存路径不等于
完整的独立副本操作。复用/抽取已验证的项目复制规则，核对所有入口、完整源数据、
内嵌元件和引用关系；不能只清空绑定或漏复制新加入的持久化字段。
副本不继承 Cloud/Gallery 关联、本机写入授权、历史归属或恢复会话。

保存只在落盘成功后确认。取消、磁盘满、权限失败或目录失效不改变当前绑定和
脏状态；并发写入继续使用版本/已确认内容检查。写入期间发生的新编辑仍属未保存。
新项目和副本须有防重机制，重复点击或重试不会产生多份；失败残留能在重启时清理
或恢复，不能将半成品列成正常项目。

## 4. 项目管理、历史与工作区

项目主页提供项目库列表、最近打开、名称搜索、修改时间排序、收藏、新建、打开、
复制、重命名、导出、历史和定位文件。首次无项目时可以直接新建；有工作区时
恢复项目标签和当前页，并能随时返回项目管理。继续使用共享编辑器和现有视觉风格。

列表及打开标签反映同一保存结果；不会展示过期状态再覆盖新文件。重复打开同一
存储目标聚焦已有标签。不同路径的文件即使携带相同 Project 身份也不能误合并。
文件被移走或损坏时显示异常条目和重新定位入口，不静默新建同名空项目。

保存历史对齐线上当前规则：每次内容变化的成功 Save 保留被替换版本，最近三个
先前版本之外才可清理；无变化重试不产生历史。支持查看/比较、恢复、基于历史
建立独立项目。恢复前保护当前版本并检查冲突；有未保存编辑时先处理保存/放弃。
历史与当前文件提交须可崩溃恢复；历史写入失败时本轮 Save 失败，保留原文件。
外部文件的历史存于应用管理位置，以存储目标归属；导出单个项目文件不携带历史，
界面明确此差异。完整项目库备份须在停止写入后包含项目、管理元数据和历史。

“从最近列表移除”只移除快捷记录；“删除项目”是明确的数据操作。首版项目库
删除采用可恢复的回收区，并支持恢复/显式清空；外部文件只提供移除记录和定位，
不提供静默磁盘删除。打开且未保存的项目删除前先处理未保存状态，删除后旧标签
不能继续写回。恢复同名/同身份条目时不能覆盖另一个现有项目。

正常重启恢复已保存标签；崩溃后提示未保存恢复副本。恢复副本不是原文件写入授权：
确认原文件未变化后才能重新绑定，否则作为未绑定副本打开并提示冲突。恢复数据
仍采用已有有界保留策略；删除、清空和过期处理须让用户看见，不无限增长。

## 5. 最小绘图与交换能力

采用主线已有的模型、元件定义、事务、连通计算、文件协议和导出器。保留：

- 元件检索/放置、选择、移动、旋转/镜像、复制粘贴、删除、属性与标签编辑；
- 连线、拐点、连接点/交叉、网络名称、Cell Pins 和电源连接语义；
- 多 Cell 层次、进入子 Cell、端口和层次网表；撤销/重做、缩放和平移；
- 当前已有的本地 ERC/视觉检查，不依赖云端拓扑查重服务；
- `.icproj.json`、SPICE/Spectre 及本地 include 导入，SVG/PNG/PDF 导出；
- SPICE/Spectre 网表预览、复制及新增的直接存文件，同一生成计划、root、配置和拒绝条件。

字体、公式渲染和导出资源随包提供。已有项目中的内嵌元件、源文件和暂不可用功能
数据必须保存往返完整；离线不执行模拟不等于允许删掉模拟配置。缺少外部依赖时
给出定位错误，不联网补取、不猜测内容。支持的历史格式升级和未来格式拒绝沿用主线。
文件交换使用显式导出/导入；同一版本两端内容往返一致，跨版本不承诺旧程序读未来格式。

## 6. 共用实现与离线构建

项目操作模块负责新建、保存、复制、重命名、历史恢复的共同规则以及结果状态；
Web Cloud 与 desktop 文件系统作为两个存储适配实现。权限、路径授权、原子写入、
目录扫描和 Windows 交互由主进程持有，renderer 只持有受约束的标识，不能任意写路径。
本地索引不成为第二份项目内容数据库，也不引入 fork Schema。

按 #1121 补齐能力工厂与导入约束：离线入口不装配 identity/community/telemetry/
simulation/agent，不包含其在线实现。构建检查使用产物模块图及辅助 API 路径检查，
保留主进程网络/导航/权限拦截。应用内部协议读静态资源及本机文件桥接属于本地操作；
外部 HTTP/WebSocket、外部浏览器交接、云轮询、service worker 和隐式更新均禁用。
UI 隐藏、模块剥离和运行时零外部请求分别验收，不能互相替代。

本轮不顺带为 Web 增加本地文件正式保存和 Cloud/文件目标选择。这是 #1121 的
独立未完成范围，需在实施来源明确标注；本轮完成不能据此关闭整个 #1121。
本地保存历史是本轮为“机制同步线上”新增的范围，区别于 #1119 排除的云端
Gallery/版本服务；在关联实施需求中明确这项范围调整。

## 7. Windows 使用、升级与分发

继续交付完整 Windows x64 ZIP；提供用户主动启用的文件关联及移除入口，并接收
冷启动和已运行时的项目路径。只注册本产品约定的文件类型，不接管全部 `.json`；
复合扩展名 `.icproj.json` 的实际 Windows 行为必须验证。若无法可靠隔离，先明确
新的外层文件关联方案并核对文件协议，不能用全局 `.json` 关联通过验收。

ZIP 解压免安装与“数据跟随程序目录”的便携模式分开；本轮使用稳定用户目录。
升级可解压到新目录，项目、设置、恢复、历史仍可访问；关联指向新版本前检查目标。
保留旧程序用于回退，但旧版不支持新数据时明确拒绝，不能静默降级写入。
旧预览的设置/最近列表/恢复记录须发现并提供一次性迁入：先验证、再复制、再启用，
保留原数据；原外部项目文件不移动。初始化/迁移中断可重试且不重复创建项目。

关于页显示应用版本、源码提交、文件格式版本、项目库位置和用户数据位置。
发布从已合入 main 的固定 SHA 构建，使用全新用户配置验收实际 EXE；安全扫描
覆盖运行产物和随附源码，继续禁止打入环境文件、服务端凭据和真实用户资料。
验收通过再发布新 ZIP、更新仓库 README 链接，网站部署不代替桌面发布。
正式安装器、签名、自动更新、macOS 和数据随 EXE 移动的便携模式仍另期处理。

## 8. 实施顺序与证据

每个目标是可验证的完整用户行为，由主项目指定 owner，从执行时 main 固定基线
开始；不以本方案编写时的旧 SHA 作为后续开发基线。实现目标进入当前仓库的
需求/Spec、验证、双轴审查和交付流程，文档目标不自动授权关闭父 Issue。

| 目标                    | 交付的完整行为                                               | 主要证据                                                   |
| ----------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| L1 默认项目库与首次保存 | 新建→编辑→Ctrl+S 自动入库→重启可找到；外部文件继续原位保存   | 真实临时目录的存储契约、EXE 首次使用/失败/重启             |
| L2 独立副本与项目管理   | 列表/搜索/收藏/重命名；另存为→切换副本→原项目不变；删除/恢复 | 两端共同操作规则、跨标签与磁盘冲突；必要的 Gallery census  |
| L3 历史与恢复升级       | 三个先前版本、比较/恢复/分支；工作区重启和旧预览迁入         | 原子写入中断、历史失败、外部修改、索引重建、旧数据 fixture |
| L4 离线绘图闭环         | 完整电路编辑、导入和图形/网表文件导出；构建剥离与零外部请求  | 共享核心回归、模块图、实际 EXE 全流程请求观测              |
| L5 系统集成与发布       | 双击文件冷/热启动、换目录升级、发行产物和下载入口            | Windows 系统关联验收、实际下载 ZIP 的干净环境验收          |

L2、L3 在 L1 的正式存储规则上推进；L4 可以在记录好共享接口后独立推进；L5
在前四项通过后收口。记录测试影响、已知限制和发布证据。涉及现有 fork 实现的
再采用或改写，先读 [固定源码索引](migration-references.md) 和
[SOURCES](../../../apps/desktop/SOURCES.md)，记录原作者/提交/复用范围，核对许可与
最终 squash 署名；不以目标名称或代码量替代贡献判断。

## 9. 本阶段完成标准

必须同时满足，才把当前离线版本标为本阶段完善：

1. 新用户解压即用，不装开发环境；新建后 Ctrl+S 自动保存到可见的本地项目库。
2. 项目列表、外部文件、Save/另存为/导出、重命名、收藏和删除/恢复按上述语义工作；
   原项目、副本及各标签互不覆盖，取消、失败和冲突不丢数据。
3. 历史与恢复各司其职，清缓存、重启、升级和索引重建不损坏正式项目；旧预览数据可迁入。
4. 用固定的完整放大器 fixture 完成 GUI 放置、连线、标签/参数、编辑、复制和撤销；
   保存后通过文件关联重开，导出 SVG/PDF/PNG 与 SPICE/Spectre，核验结构与内容。
   用户已确认使用 `apps/editor/src/examples/simulation-ota.icproj.json`，即
   `netlists/native-ota/README.md` 指定的主工程；另用其历史 `source.icproj.json`
   核对八个内嵌元件的保留。此项证明绘图/连通/导出，不宣称电气仿真正确。
5. 代表性层次项目和含本地源文件/内嵌元件的项目完成两端文件往返；不丢失未开放功能数据。
6. 上述流程在禁止联网环境运行，观测零外部请求；主动联网探针被阻止；离线产物不含在线模块。
7. 受影响 Web 行为按现行门禁通过；代码共用一套模型、事务与协议，适配差异有共同契约保护。
8. 已发布的新 ZIP、源码/许可/贡献、验收与安全记录对应同一 SHA，README 指向该产物；
   #1119 逐项核对后再关闭，#1121 未覆盖的 Web 文件存储要求继续保留。

Visio、MATLAB 色板、粗网格及其他 fork 特性不作为本阶段完成条件。它们仍按原
来源和分叉讨论单独推进。本轮交付后留下的是明确后续能力，而非基础文件管理、
绘图和离线保障缺口。
