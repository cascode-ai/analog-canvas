## 1. 语法速览

### 1.1 推荐写法

以下例子假定所引用的宿主对象、标准结构和 RNL 对象存在，所用角色由有效类型契约声明。它们用于说明语法，不是独立的完整仿真网表。

```text
* @RNL #M1 and #M2 @AS($DIFFPAIR, "input_pair")
* @RNL #M1 @AT(1, 2) position for revision 3
* @RNL %input_pair(input) and #ITAIL(tail) @AS($DIFFSTAGE, id="input_stage")
```

需要换行时：

```text
* @RNL{
*     #M1 and #M2
*     @AS(
*         type=$DIFFPAIR,
*         id="input_pair"
*     )
* }
```

### 1.2 记号职责

| 记号 | 职责 |
| --- | --- |
| `@RNL` | 开始一条行式 RNL 描述，当前物理行结束时终止 |
| `@RNL(scope=["X1"])` | 为当前记录选择目标实例层次，入口参数不是操作参数 |
| `@RNL{ ... }` | 有明确结束边界的块式封装；当前版本仍只包含一条描述 |
| `@AS(...)`、`@AT(...)` | 操作及其参数区；零参数时可写 `@OP` 或 `@OP()`；操作名不区分 ASCII 大小写 |
| `#M1`、`#X1` | 宿主器件实例、子电路实例 |
| `&out`、`&0` | 宿主网络 |
| `%input_pair`、`%sym_amp` | RNL 对象引用 |
| `$DIFFPAIR` | 类型／结构定义引用，不是另一个命名空间 |
| `#M1(in_p)`、`%input_pair(input)` | 紧邻主对象引用的角色标注 |
| `"input_pair"` | 字符串值；用作 `id` 时是新名字，不是引用 |
| `(1, 2)` | 仅在操作之后作为参数区时，表示两个位置参数 |
| `(x=1, y=2)` | 具名参数；可以与前面的连续位置参数混合 |
| `[1, 2]`、`{"a":1}` | 参数区内的数组和映射 |

`$` 是单边前缀，不再采用 `$DIFFPAIR$`。所有操作参数必须在该操作的圆括号中，不允许括号外的位置参数；零参数调用可以省略整个参数区。

### 1.3 四项核心约束

1. **宿主隔离。** 只有宿主确认属于普通注释的内容，才可能承载 RNL。
2. **正式内容有边界。** 对象引用有前缀；操作有 `@`；操作参数有圆括号。无标记的数字或单词不被猜测成参数。
3. **唯一名称解析。** RNL 类型、语义对象、符号、虚元件、资源等共享作用域内的一张命名表；前缀和角色标注不用于挑选同名候选。
4. **电气事实不变。** 语法、引用和单条描述基本规则需要检查；绘图与宿主电气连接的一致性不属于强制检查。

## 2. 不变的原则与边界

本章概括原则稿 [P]，不扩大其要求。

### 2.1 RNL 的定位

RNL 是附着于原网表的纯数据元信息。完整文件仍按宿主原有方式交给仿真器，不要求先剥离或转换 RNL。不同 SPICE 方言、Spectre 等宿主语言本身的互换不由 RNL 解决。

RNL 以电路结构语义、设计意图及声明式呈现为主。仅有语义而没有坐标的描述是合法输入。RNL 不要求唯一布局、像素一致或编辑往返图形不变。

### 2.2 电气单一来源与不校验原则

器件身份、宿主器件类型、模型、参数、端子顺序、网络连接和子电路接口只由宿主定义。RNL 可引用它们或设置显示别名，不能重定义它们。

以下情况不能仅因电气不一致而被判为 RNL 基本错误：

- 两个不相连的宿主端子之间画了一条视觉路径。
- 路径关联的网络不属于其任一端点。
- 端口位置重合、线条接触或交叉。
- 声明的结构与宿主器件类型、参数或实际连接不一致。

实现可以额外检查和提示，但必须与标准要求的基本检查区分。引用不存在的对象、参数类型不合法、或一条差分对描述重复引用同一对象，则仍可以构成基本错误。

### 2.3 虚元件与 note

虚元件只用于显示，可以有显示端子和宿主网络关联，但不创建电气器件或连接。note 是无端子的自由文字、图形或边框。二者均由 RNL 拥有，不写入宿主电气模型。

### 2.4 纯数据

解析、名称绑定、结构解释和资源处理不得执行代码或隐式访问网络。类型名称、操作名称和资源字符串不能自动触发插件下载或任意脚本执行。

## 3. 宿主注释与 RNL 封装

### 3.1 两层解析

**【已确认】** 宿主适配器负责识别合法普通注释、作用域、物理来源以及有效输入顺序；RNL 核心负责在这些注释内容中识别 RNL 片段。

不能对整个网表做无上下文的 `@RNL` 搜索。宿主正文、字符串、加密区域、内嵌语言或专用预处理区域中的相同字符序列，不因此成为 RNL。

适配器应保留注释内容中的空白和源位置，不能先对每行执行 `trim()` 再做 RNL 识别。

### 3.2 安全空格

**【已确认】** 作为入口或操作使用的 `@`，紧前一个字符必须是 ASCII 空格 U+0020。这个要求不适用于字符串或带引号名称中的 `@`。

```text
* @RNL #M1 @AT(1, 2)
```

这里 `@RNL` 和 `@AT` 前均有空格。单个 TAB 或仅有换行不替代这个必需空格；其它位置仍可使用 TAB 缩进。抽取载荷时不得丢掉用于此项判定的空格。

采用星号整行绑定时，每条承载 RNL 的物理注释行必须采用宿主允许的位置写入 `*`，然后至少一个 ASCII 空格，再写内容。可移植的推荐形式是第一列 `*`。

```text
* @RNL{
*     #M1
*     @AT(1, 2)
* }
```

不能输出 `*@RNL`，也不能把续行压缩成 `*#M1`。WRspice 的官方帮助明确给 `*@`、`*#` 行以命令含义，并建议普通注释在星号后留空格 [W1]。该证据支持保留空格，不是所有仿真器兼容认证。

### 3.3 注释绑定

| 载体 | 条件及规则 |
| --- | --- |
| `* ...` 整行注释 | 仅在当前宿主上下文确认其为普通注释时使用；`*` 后保留空格 |
| `// ...` 整行注释 | 仅在宿主支持时使用；建议 `//` 后保留空格 |
| `/* ... */` 等块注释 | 仅在宿主支持时使用；内部每行不要求伪造行注释标记 |
| 宿主行尾注释 | 仅在适配器明确支持并确认预处理安全时使用；不作为默认可移植输出 |

此表是条件化载体接口，不表示所有 SPICE 方言均支持后三项。星号注释本身在 MacSpice 文档中有说明 [W2]；其他工具和模式应分别验证。

宿主的标题行、结束标记、续行、编码、行长和预处理限制始终优先。RNL 不授权在特殊首行、活动宿主语句中间或不可确认的控制区域插入元数据。

### 3.4 入口识别

**【已确认】** 入口单词 `rnl` 按 ASCII 大小写不敏感匹配；无需处于注释正文的开头。

```text
* Input stage: @RNL #M1 #M2 @AS($DIFFPAIR)
```

**【已确认】** 入口可以携带仅影响当前记录的参数，例如 `@RNL(scope=["XTOP", "XIN"])`。scope 从操作参数移至入口；不改变宿主网表，也不作用于后续记录。

**【本稿补全】** 入口参数区必须紧贴 RNL，且在入口所在物理行内闭合；可省略或写空括号。只允许具名 scope，值为字符串数组；未知字段、重复字段和位置参数均报错。参数区内使用通常的值与逗号规则，`=` 两侧允许空白。`@RNL (scope=...)` 非法。头部出错使整条记录失效，恢复遵循 3.8，不把剩余片段当作有效无参数入口。

在入口单词及可选参数区之后，按以下方式选择封装：

- 紧接 `{`，或只经过空格／TAB 后遇到 `{`：块式。
- 后面至少有一个空格／TAB，且当前物理行的后续内容不是上述块起始：行式。
- `@RNLX` 等较长标识不等于入口；只有入口头部、没有描述是空记录错误。
- 入口头部与用于选择块式的 `{` 之间不跨物理换行；需要多行时把 `{` 留在入口所在行。

普通注释中展示例子但不使其生效，可将入口写成 `\@RNL`；此时 `@` 前不是空格，所以不构成入口。这只是在 RNL 片段之外禁用入口的文本写法，不新增 RNL 参数字符串转义。

### 3.5 行式封装

```text
* @RNL #M1 #M2 @AS($DIFFPAIR, "input_pair")
```

从入口头部之后开始，到当前物理行结束或当前宿主注释区域结束，以较早者为界。终止边界不属于载荷。

一条行式记录只含一条描述。即使参数括号未闭合，也不能自动延续到下一行。第二个 `@RNL` 不能用来在同一条行式记录中继续写另一条描述。

行尾辅助文字属于当前载荷。需要在一行中放置多个独立片段时，使用显式结束的块式。

### 3.6 块式封装

```text
* @RNL{ #M1 @AT(1, 2) }
```

或：

```text
* @RNL{
*     #M1
*     @AT(
*         x=1,
*         y=2
*     )
* }
```

规则：

1. 最外层 `{`、`}` 仅用于确定片段边界，不进入描述语句。
2. 当前版本块内恰好一条描述，不是语句列表，不允许嵌套 RNL 封装。
3. 大括号不引入作用域、分组、默认属性、事务或覆盖优先级。
4. 内部参数映射的 `{}` 参与括号配对；合法字符串中的括号不参与配对。
5. 在行注释载体中，块只能跨越同一物理文件、同一宿主语言及作用域中的连续合法注释行。注释空行可以；未被宿主划为注释的空物理行不自动加入块。
6. 在块注释载体中，不能超出当前宿主块注释的结束位置。
7. 不能跨宿主正文、include 边界、子电路边界或语言切换拼接。
8. 块结束后回到宿主注释扫描状态；若后面有另一个合法入口，可以开始另一条记录。

```text
* @RNL{ #M1 @AT(1, 2) } @RNL{ #M2 @AT(3, 2) }
```

上例为两条记录。交换它们的顺序仍可能影响覆盖；格式化器不能随意重排。

### 3.7 换行与宿主终止序列

**【已确认】** 换行保留为词法空白，不直接无分隔拼接两行文本。不能把 `DIFFPAIR`、一个数值、名称或 `\uXXXX` 转义拆成跨行片段。字符串不允许裸换行。

行式转块式后可在词法单元之间换行；块式转行式须确认未改变辅助文字边界、必需空格和紧邻角色标注。

宿主注释终止序列优先于 RNL 字符串。例如某载体以 `*/` 结束注释，RNL 双引号不会保护内部的 `*/`。生成器必须选择安全编码或其他绑定；可在 JSON 风格字符串中使用 `*\/` 表达相同的解码字符。

### 3.8 入口错误恢复

**【本稿补全】** 一条行式记录出错，恢复到其结束边界之后。块式在匹配外层 `}`、宿主注释硬边界或 EOF 处完成或失败。

未完成的块中，在合法字符串之外遇到新的独立 `@RNL` 入口，旧记录失效，扫描器从新入口重新开始；这不是嵌套语法。若字符串本身损坏，恢复器可以在下一个物理行重新寻找独立入口，但必须把受影响的原记录判为错误，不得将其截断部分当作有效描述。

恢复目标是让下一条独立记录仍可读取，不要求凭损坏文本推测作者原意。一个错误语句的恢复范围不能自动扩散到整个文件。

## 4. 字符、空白和名称

### 4.1 字符与编码

结构标记均为 ASCII。字符串采用第 8 章的转义。写入已有网表时不得因增加 RNL 而改变宿主编码、换行或增添 BOM。

**【本稿补全】** 推荐可移植输出只使用 ASCII；非 ASCII 名称和文字通过字符串内的 Unicode 转义表示。适配器明确支持相应宿主编码时，可以接受直接 Unicode 字符串。辅助文字的基础语法使用第 5 章列出的 ASCII 字符。

本稿不规定一个声称适用于所有仿真器的最大行长。生成器应遵守其声明支持的宿主限制。若一个不可拆分的字符串或名称本身超过宿主行长，不能仅靠块式封装绕过限制；需要改用支持的载体／资源表达。通用语法不自动把相邻字符串或字符串数组拼成一个字符串。

### 4.2 大小写

| 内容 | 比较规则 |
| --- | --- |
| `@RNL`、`@AS`、`@AT` 等入口与操作名 | ASCII 大小写不敏感 |
| 宿主对象名、宿主端子名和实例路径段 | 宿主适配器的名称规则 |
| RNL 自有对象名、类型名、显示端子名 | 本稿采用区分大小写的解码字符串比较 |
| 具名参数名 | 本稿采用区分大小写；核心字段使用小写 |
| 映射键、普通字符串 | 保持原值，不作自动大小写或 Unicode 归一化 |
| `true`、`false`、`null` | 仅接受小写字面量 |

`@AS` 与 `@as` 等价，不意味着 `$DIFFPAIR` 与 `$diffpair` 等价。不能为了标准化操作而对整行或整份文件转小写。

### 4.3 词法空白

一般词法空白为 ASCII 空格、TAB 以及块载荷中的规范化换行。CRLF、LF 可在解析视图中归一化为换行，但编辑器保留源文件原始形式。

下列位置有额外要求：

- 入口或操作的 `@` 紧前必须是 ASCII 空格。
- `#`、`&`、`%`、`$` 与后面的名称之间没有空白。
- 端子选择器的冒号两侧没有空白。
- 角色标注的左括号必须紧贴完整主对象引用（含端子选择器）。
- 入口名、操作名与其参数左括号之间不能有空白。操作参数可以在紧邻的左括号之后按块式规则换行。

### 4.4 名称写法

**【本稿补全】** 未加引号的简单名称为一个或多个 ASCII 字母、数字、下划线：

```text
[A-Za-z0-9_]+
```

因此 `M1`、`input_pair`、`0` 都可以作为引用中的名称。是否为有效宿主名称仍由宿主确认。简单名称采用最长匹配，不在中途拆分。名称在第一个不属于其词法的字符前结束；后续字符仍须按上下文解析，不能直接删除。

其他名称使用双引号：

```text
#"M1<0>"
&"VDD!"
%"input pair"
$"acme.diffpair"
#"X1.M1"
```

`.`、`/`、`-` 等未列入简单名称，是为了避免与辅助标点及其他语法含混；需要这些字符时应加引号。`#"X1.M1"` 是一个完整的本地名称，不是层次路径。

RNL 自有名称必须非空；本稿不允许其中包含 C0 控制字符或 U+007F。引号不创建另一张命名表，`%input_pair` 与 `%"input_pair"` 指向同名对象。宿主名称经 RNL 字符串解码后交给宿主适配器，不额外施加 RNL 自有名称的字符规则。

### 4.5 宿主转义与 RNL 转义

引用的是宿主解析后的本地对象名称，而不是盲目复制宿主源文件中的转义拼写。RNL 不统一各宿主的反斜杠、大小写和特殊名称规则。

RNL 字符串里的 `\\` 表示名称中的一个反斜杠。不能一概删掉宿主名称里的反斜杠、把数字节点转成整数，或把句点拆成路径。

## 5. 描述语句与辅助文字

### 5.1 固定结构

一条描述由以下内容组成：

```text
辅助文字／有序主对象引用（可附角色）  @操作(参数)  辅助文字
辅助文字／有序主对象引用（可附角色）  @零参数操作  辅助文字
```

正式结构是：零个或多个主对象引用，加且仅加一个操作调用。主对象在操作之前，通用语法将其保存为有序变长数组；操作要求几个主对象、允许哪些类别，由操作及其类型定义决定。

```text
#M1 and #M2 form a pair @AS($DIFFPAIR, "input_pair") input stage 1
```

主对象为 `#M1`、`#M2`，操作为 `as`，位置参数为类型引用和字符串。其余单词与数字不参与解释。

### 5.2 有参数时必须使用参数区

**【已确认】** 没有参数时，`@OP` 与 `@OP()` 都表示零参数调用；有参数时，所有参数必须位于操作的圆括号中。是否接受零参数由操作契约决定，不存在括号外的位置参数。

操作名按最长匹配读取；紧接 `(` 时解析参数区。若仅隔词法空白后遇到 `(`，则报告参数括号未紧邻的语法错误，不回退为零参数调用加辅助括注。其余情况是零参数调用，后续允许的辅助文字仍无语义。不能根据操作需要的参数数量把外围文字重新解释成参数。`@RNL` 仍是入口，不是零参数操作。

```text
#M1 @AT 1 2
```

上例在通用语法层表示零参数 `at` 加辅助文字 `1 2`；按本稿 `at` 必须至少指定一个坐标的契约，整条描述失效。数字不会自动成为参数。对于允许零参数的操作，类似外围数字只是辅助文字，不要求推断作者是否漏写括号。

```text
#M1 #M2 @AS $DIFFPAIR input_pair
```

上例同样失效。`$DIFFPAIR` 不因有前缀就获得括号外参数资格。

### 5.3 辅助文字

**【已确认】** 参数区、正式引用及角色标注之外，允许 ASCII 字母、数字、一般词法空白和下列标点作为辅助文字：

```text
. , ; : ! ? ' - _ / + * < > | ( ) [ ] = " \
```

`@ # & % $ { }` 仍保留给正式语法和封装，不能在辅助区域任意使用。保留字符出现在不允许的位置时是错误，不自动降格为说明文字。`()`、`[]`、`=`、`"`、`\` 则按所在上下文解释，不全面保留。

正式结构优先于辅助文字：

- 完整主对象引用后紧邻的 `(` 开始角色标注。
- 操作名后紧接的 `(` 开始参数区；仅隔空白再出现 `(` 是语法错误。
- 一旦进入上述正式结构，必须按相应语法解析至其结束；失败不能回退成辅助文字。
- 其余辅助位置允许自由圆括注、方括注、等号、双引号和反斜杠。这些字符不形成参数、数组、赋值或字符串，也不要求配对。

辅助文字中的双引号不保护内部的正式标记，反斜杠也不转义后续字符；它们只是普通字符。例如辅助位置的 `" @AT(1, 2)"` 仍包含满足空格条件的操作标记，不能用引号隐藏第二个操作。块式封装中的 `}` 也不会因辅助引号而失去结束作用。第 3.4 节在片段之外禁用入口的写法不因此成为片段内转义规则。

需要表达仍被保留的字符时，应使用操作的字符串参数，或把说明放到 RNL 片段之外。正式字符串的保护及转义规则保持不变。参数区内不允许辅助文字、行内注释或自然语言插话。

辅助文字可以在主对象之间以及操作之后出现，但不能插入正式标记内部。`@AT position (x=1, y=2)` 表示零参数 `at` 加辅助文字，不等价于 `@AT(x=1, y=2)`，并因不满足 at 的字段要求而失效。对于接受零参数的操作，同类外围括注可以合法存在。

主对象后的辅助标点可以紧贴名称，例如 `#M1, #M2` 是两个对象及一个辅助逗号，`#M1!` 是对象加辅助感叹号。若感叹号属于真实名称，应写 `#"M1!"`。冒号端子选择器和紧邻角色括号仍按正式语法优先识别，损坏时不得剥离后缀来修复引用。

操作名也按其词法最长匹配：`@OP, reviewed` 可以是零参数操作加辅助标点；`@OP(...)` 的右括号后可以紧跟逗号。点若后接合法标识符则属于点分操作名，例如 `@ACME.ROUTE`；否则可作为辅助句点。参数区内的逗号始终是参数分隔符，不是可剥离的辅助标点。

### 5.4 辅助文字不改变含义

```text
#M1 and #M2 do not form a pair @AS($DIFFPAIR)
```

仍然声明差分对。`not`、`if`、角色词及普通数字均无语义。显式角色使用第 7 章的正式标注；否定或条件需要将来明确支持的正式字段／操作，不猜测自然语言。

丢失整个标记后，有些内容可能退化为合法辅助文字；标准不要求识别所有此类作者意图错误。例如：

```text
#M1 @AT(1, 2) (unexpected)
```

中的 `(unexpected)` 是合法辅助括注，与下例的正式含义相同：

```text
#M1 @AT(1, 2) unexpected
```

中的 `unexpected` 是合法辅助文字。类似地，`#M1 (in_p)` 只表示未标注角色的对象加辅助括注，不等价于 `#M1(in_p)`；标准不要求检测所有这类紧邻关系丢失。

### 5.5 对象顺序

**【已确认】** 所有对象列表在语法层都是有序列表，解析器必须保留顺序。操作或类型契约决定顺序的语义：可以按位置绑定角色，也可以规定任意排列等价。参数数组和同一角色的多对象列表同样保留顺序。辅助文字中的 `input`、`tail` 等单词不分配角色；显式角色使用第 7 章的紧邻标注。

主对象只在操作前收集。参数里的 `#M1`、`%pair`、`&out` 属于参数值，不自动增加主对象。操作后出现新的正式引用，在本版不是追加主对象，而是语法错误。

## 6. 对象、端子与类型引用

### 6.1 四种基本前缀

| 形式 | 解析对象 | 不表示 |
| --- | --- | --- |
| `#name` | 当前电路层次中的宿主器件／子电路实例 | 子电路定义名、模型名或新器件声明 |
| `&name` | 当前层次中宿主可解析的网络 | 数值或新建节点 |
| `%name` | RNL 非类型对象，包括语义对象、符号、资源、虚元件、note 等 | 创建新对象或根据前缀猜测其具体类别 |
| `$name` | RNL 类型定义，例如结构定义或虚元件类型 | 操作关键词、字符串字面量或插值变量 |

**【本稿补全】** 本版采用上表的表面类别区分：`%` 引用非类型对象，`$` 引用类型定义。二者仍查同一张命名表；只有找到唯一有效绑定之后才检查类别。不同时引入“`%` 也能任意引用类型”的第二种短写法。

`$1` 是对名称 `1` 的类型引用，不是数值 1；`$A` 是类型引用，不是字符串 `"A"`。数值和字符串依靠参数区域确定其为正式值，不分配额外前缀。

### 6.2 端子选择器

**【已确认】** 为避免为每种端子增加一个前缀，采用紧邻冒号选择器：

```text
#M1:1
#M1:d
#"M1<0>":"d"
%g0:p
#:1
#:"INP"
```

| 形式 | 含义 |
| --- | --- |
| `#M1:1` | M1 的第一个宿主端子 |
| `#M1:d`、`#M1:"d"` | 宿主适配器明确提供的名为 d 的端子 |
| `%g0:p`、`%g0:"p"` | RNL 对象 g0 的命名显示端子；对象必须具有端子 |
| `#:1`、`#:"INP"` | 当前子电路接口的端口，不是其父层某个实例的端子 |

冒号前后不允许空白，不允许链式选择器。当前接口采用 `#:`，没有虚构一个名为 `self` 的宿主器件，也不引入新命名空间。

在宿主端子和当前接口选择器中：未加引号的正整数表示从 1 开始的端子序号；字母／下划线开头的简单名或引号字符串表示名称。`#M1:0` 非法；`#M1:"0"` 可以引用一个真实名为 `0` 的端子。指数、负数、前导零索引不允许。

对 RNL 显示端子，选择器始终是名称；`%g0:1` 表示名为 `1` 的显示端子，不是第一个端子。其名称由 RNL 对象的显示端子定义决定。

宿主端子序号来自适配器解析后的端子列表，不是空白分隔字段的位置，也不是封装焊盘号。没有明确命名端子信息时，不能凭 MOS、BJT 等惯例猜测 `d`、`g`、`s`。

`#:` 只在有宿主子电路接口的上下文中有效。顶层没有接口时不能用它代替某个普通网络。

### 6.3 简单名称中的标点

名称含冒号时加引号：

```text
#"M1:branch"
#"M1:branch":1
```

第一条引用完整器件名；第二条再选择其第一端子。`#M1:branch` 则明确是端子选择器。同样，引用 `VDD!` 写 `&"VDD!"`，避免感叹号被作为辅助标点。

### 6.4 引用身份与存在性

宿主对象身份由适配器给出。宿主不区分大小写时，`#M1` 与 `#m1` 可能是同一个对象，不得用于规避“两个不同对象”的规则。

RNL 对象按目标作用域中的唯一有效绑定识别。`%sym_amp` 不因为以 `sym_` 开头就被视为符号；它可能定义成其他类别，随后在使用位置发生类型错误。

引用不存在的对象、网络、端子或接口是基本错误。引用存在但电气上不符合作者的结构解释，不自动成为基本错误。

### 6.5 不进行跨层次解码

```text
#"XU1.M1"
%"library::shape"
```

都按完整本地名称处理，不拆成层次或库路径。进入子层次使用入口参数 `@RNL(scope=...)`。从其他物理文件包含进来的对象，若在同一可见电路层次，仍用普通本地引用。

## 7. 紧邻角色标注

### 7.1 语法与边界

**【已确认】** 主对象可以附加紧邻角色标注，表达它在当前描述中承担的职责：

```text
#M1(in_p)
#M1:1(source)
%pair(input)
&out(output)
```

左括号必须紧贴完整对象引用，包括已有的端子选择器。括号内恰好一个角色名，允许内部词法空白；不能链式追加多个标注。标注只用于操作前的主对象条目，不适用于参数值中的引用，也不附在 `$` 类型引用之后。

**【本稿补全】** 角色名采用第 4.4 节的简单名称或引号字符串，解码后按 RNL 自有名称规则检查非空和控制字符，区分大小写。例如 `#M1("positive input")`。引号不改变角色身份。角色属于当前操作或类型的契约，不进入 RNL 对象命名表。

```text
#M1(in_p) and #M2(in_n) with #ITAIL(tail) @AS($DIFFSTAGE, "stage")
```

此例以有效类型定义确实声明这些角色为前提；不将示例角色名规定为标准库最终契约。`and`、`with` 是辅助文字；括号中的角色是正式内容。

### 7.2 顺序绑定与显式绑定

**【已确认】** 主对象列表采用同一种条目结构：对象引用及其可选角色标注。一条描述要么所有主对象均标注角色，要么全部省略；不允许混用后推断遗漏角色。零主对象操作是否合法由契约决定。

- 全部省略时，按操作或类型契约解释列表顺序；位置角色和任意排列等价都必须明确声明。
- 全部标注时，按角色名绑定，不再用条目的全局位置猜测角色；原始列表顺序仍须保留。
- 单对象角色不能重复；多对象角色允许重复出现，并按出现顺序收集对象。该角色契约决定组内顺序是否有语义。
- 未知角色、缺少必填角色、角色数量或对象类别不合要求，都使整条描述失效。
- 同一对象是否可以承担多个角色，由契约决定，不能通过不同拼写绕过对象身份检查。

当 `in_p` 和 `in_n` 是单对象角色时，下列两条的角色绑定相同：

```text
#M1(in_p) and #M2(in_n) @AS($DIFFPAIR)
#M2(in_n) and #M1(in_p) @AS($DIFFPAIR)
```

角色契约应公开角色名、含义、允许的对象类别或声明类型、数量、必填性、重复限制及无标注时的顺序规则。复杂或不对称结构建议优先输出角色标注，以减少生成者记忆位置顺序的负担；这不是已经完成的 LLM 可靠性实验结论。

### 7.3 与参数区及类型检查的区别

`#M1(in_p)` 的括号属于主对象角色，`@AT(1, 2)` 的括号属于操作参数区。`#M1 (in_p)` 是未标注角色的对象加辅助括注，不进行角色绑定；`@AT (1, 2)` 非法，因为操作与参数区必须紧邻。角色标注不允许 `$` 类型引用、赋值或多个逗号分隔的值。

先解析对象及有效操作／类型定义，再按照角色契约检查对象类别和所需声明类型；不因期望类型而回退查找较早、父层或标准库中的同名候选。类型可以通过继承和扩充形成新类型；具体定义语法及类型兼容规则仍待定义，不由角色标注推断。

角色是本条描述中的职责，不改变对象本身。同一对象在不同描述中可以承担不同角色。角色检查不强制验证宿主电路是否真实构成所声明拓扑。

## 8. 参数和值

### 8.1 参数列表

参数全部位于一个操作的圆括号中，以逗号分隔。允许：

```text
@AS($DIFFPAIR)
@AS($DIFFPAIR, "pair")
@AS($DIFFPAIR, id="pair")
@AS(type=$DIFFPAIR, id="pair")
```

以上为操作片段展示；嵌入正式载荷时 `@` 前仍需空格。

语法支持空列表 `()`，但具体操作可以要求至少一个参数。

**【本稿补全】** 不允许尾随逗号。禁止同一列表里重复参数名；按位置和名称重复赋予同一字段也禁止。数组、映射同样不允许尾随逗号。

### 8.2 值类别

支持以下值：

| 值类别 | 示例 |
| --- | --- |
| 字符串 | `"pair"`、`"Input stage"` |
| 数值 | `1`、`-2.5`、`1e-3` |
| 布尔值 | `true`、`false` |
| 空值 | `null` |
| 数组 | `[1, 2]`、`[#M1, #M2]` |
| 映射 | `{"inp":[0,2], "out":[8,4]}` |
| 宿主对象引用 | `#M1`、`&out`、`#M1:1`、`#:"INP"` |
| RNL 对象引用 | `%pair`、`%sym_amp`、`%g0:p` |
| 类型定义引用 | `$DIFFPAIR`、`$"custom pair"` |

类型、引用和容器都是数据，不发生表达式求值或字符串插值。参数区中不接受未加引号的普通字符串，例如 `id=pair`。

### 8.3 字符串

字符串词法沿用 RFC 8259 的相应形式 [W3]；数值采用第 8.4 节扩充的十进制词法，整个 RNL 参数语言不是 JSON。

字符串以双引号包围；支持：

```text
\"  \\  \/  \b  \f  \n  \r  \t  \uXXXX
```

`XXXX` 为四位十六进制。可以用合法的 UTF-16 代理对转义表示非 BMP 字符；本稿拒绝未配对代理项，解码结果必须是 Unicode 标量值序列。

字符串内的 `@`、`#`、`$`、`%`、圆括号和大括号均为字符，不触发 RNL 正式标记。

```text
"Example: @AS($DIFFPAIR)"
```

是一个字符串，不是嵌套操作。

禁止单引号字符串、反引号字符串、裸换行和未经定义的转义。字符串中的换行应写 `\n`；不能使用宿主续行规则延续 RNL 字符串。

### 8.4 数值

**【已确认】** 数值使用十进制，允许正负号、前导零、省略小数点前的零、省略小数点后的数字，以及指数。例如：

```text
0
+1
01
.5
1.
-2.5E-4
+.5
01e2
```

`01` 按十进制解释为 1，不引入八进制。小数点前后至少有一位数字，指数部分必须含数字；单独的 `+`、`-`、`.`、`1e` 都非法。数字内部不能有空白。

不接受工程后缀 `10k`、十六进制 `0x10`、`NaN` 或 `Infinity`，也不进行表达式求值。原宿主参数表达式仍是宿主信息，不在 RNL 再求值。

**【本稿补全】** 通用语法保存数值的十进制含义和源拼写，不在词法阶段强制截成固定宽度浮点数。字段是否要求整数、正数、范围或某种计算精度，由操作／字段契约规定。实现超过资源限制时应诊断，不得静默改变数值或索引。

引用名称 `&01` 仍是网络名字符串 `01`。端子索引采用独立的无前导零正整数语法，不随普通数值的放宽而改变。

### 8.5 数组与映射

数组有序，可以包含不同类型的值；字段契约可以进一步限制元素类别和长度。

映射键必须是双引号字符串，键在解码后不得重复。键顺序没有语义，值递归采用本章值语法。RNL 对重复键直接报错，是本草案的收紧规则，不是借用“后者覆盖”。

```text
@APPEAR(symbol=%sym_amp, bind={"inp":#X1:1, "out":#X1:2})
```

这只是操作接口的语法示意；`appear` 的完整字段契约不由通用映射语法自动定义。

### 8.6 null、缺失与省略

`null` 是显式值，不等于未提供参数。某字段只有明确允许时才接受它。

位置参数不能用空逗号跳过：`@AT(,2)` 非法。`@AT(null,2)` 是两个参数值，按本稿 `at.x` 不接受 null 的契约应判错，不能把 null 当成“自动寻找下一个位置”的占位指令。

## 9. 操作签名与参数绑定

### 9.1 操作签名

**【已确认】** 通用机制将主对象作为零个或多个条目组成的有序变长数组传给操作，不规定固定长度。操作及其有效类型契约决定接受任意数量、范围或固定数量，并负责合法性及处理方式。

每个操作定义应说明：主对象数量约束、角色契约及顺序语义、允许的主对象类别、按位置可赋值的有序字段、仅可具名的字段、每个字段的值类型和默认值、返回／创建的对象，以及基本错误和覆盖单位。

值的类别、参数角色、必填性是不同维度。对象引用也可以是参数；必填参数也可以用具名形式。

### 9.2 连续位置前缀

**【已确认】** 位置参数绑定操作签名中从第一个字段开始的连续前缀。出现具名参数以后，不得继续出现位置参数。不按值的类型猜测它应该跳到哪个字段。

`@AS` 的位置顺序为 `type`、`id`：

```text
@AS($DIFFPAIR)
@AS($DIFFPAIR, "pair")
@AS($DIFFPAIR, id="pair")
@AS(type=$DIFFPAIR, id="pair")
@AS(id="pair", type=$DIFFPAIR)
```

最后四种给出相同的 `type` 和 `id`，规范化后的参数映射相同。

以下不合法：

```text
@AS("pair", type=$DIFFPAIR)
@AS(id="pair", $DIFFPAIR)
@AS($DIFFPAIR, type=$DIFFPAIR)
@AS($DIFFPAIR, "a", id="b")
```

分别涉及错误的位置绑定、具名后追加位置参数或重复赋值。同条语句中的重复赋值不会触发多条描述间的覆盖规则。

### 9.3 绑定过程

1. 解析入口参数及目标上下文；将操作名按 ASCII 小写归一化后查找操作契约。
2. 保持主对象引用及角色标注的顺序，检查全标注或全省略；不要从说明文字推导角色。
3. 按签名顺序依次绑定位置参数，超过允许数量即错误。
4. 按字段名绑定具名参数；未知字段和重复赋值均为错误。
5. 对未赋值字段按契约应用默认值或保留省略状态；缺失必填字段即错误。AT 的省略字段不得补成重置坐标的值。
6. 解析作用域、引用和类型，按有效契约绑定主对象角色，进行字段范围及单条基本语义检查。
7. 全部通过后，该条描述才可以创建对象或更新属性。

实际实现可分阶段或延迟完成第 6 步，以支持前向引用，但不能因为扫描时目标未出现就立即判其不存在。

### 9.4 创建名称与引用

```text
@AS($DIFFPAIR, "pair")
```

`"pair"` 是结果名称。

```text
@AS($DIFFPAIR, %pair)
```

第二个参数为对象引用，不是名字字符串；按 `as.id` 契约应判错。RNL 不把 `%name` 在某些位置重新解释成声明一个新名字。

### 9.5 入口上下文与定义属性

**【已确认】** `scope` 是 `@RNL` 入口的具名参数，不是任何操作的参数。它选择整条描述的目标电路层次，等价于把该条描述写在指定实例对应的 subcircuit 上；主对象、参数引用及创建的 RNL 对象都在目标上下文中解释。其具体路径规则见第 10.4 节。

**【本稿补全】** 可复用定义操作可支持仅具名的 `inherit`，控制定义是否向后代可见。它不移动描述，与入口 `scope` 不同。具体描述如 `AS`、`AT` 不接受 `inherit`；文件版本声明不接受作用域入口参数。

### 9.6 规范化结果

通用解析应能得到相当于以下结构的数据，不要求实现使用此 JSON 表示：

```json
{
  "operation": "as",
  "context": {"scope": []},
  "subjects": [
    {"kind": "host-instance", "name": "M1"},
    {"kind": "host-instance", "name": "M2"}
  ],
  "arguments": {
    "type": {"kind": "type-reference", "name": "DIFFPAIR"},
    "id": "input_pair"
  }
}
```

若主对象写为 `#M1(in_p)`，其条目另保存 `"role": "in_p"`；无标注时不伪造角色名。角色信息不放入操作参数映射，原始主对象顺序始终保留。

辅助文字不出现在参数映射中，但编辑器可以保留它及原始排版。示例 context.scope 为空表示默认上下文；非空时来自入口而非操作参数。物理源位置始终独立保留，不因目标 scope 改变而改写。

## 10. 单一命名表、作用域和继承

### 10.1 名称唯一性

**【已确认】** RNL 类型定义、语义对象、符号、虚元件、note、资源和其它自有命名对象在同一有效作用域共享一张命名表。不存在 `sem`、`symbol`、`resource` 等分别允许同名对象并存的名称空间。

名称只负责定位；定义决定类型；使用位置及角色契约负责类型检查。`sym_`、`note_` 等前后缀是可读性习惯，不参与解释。引用没有 `%类型:名称` 形式。

统一命名仅指 RNL 自有名字；不强迫宿主器件与网络也加入这张表。例如 `#M1`、`&M1`、`%M1` 可以分别引用宿主实例、宿主网络和 RNL 对象，按各自体系解析。

### 10.2 覆盖不是并存

同名重定义按作用域与顺序选出一个有效绑定，不产生可按类型访问的两个对象。若当前有效的 `DIFFPAIR` 是 note，`$DIFFPAIR` 就是引用类别错误；不能因此跳过 note 去寻找标准类型。

**【本稿补全】** 不额外禁止一次合法重定义改变对象类别；后续使用点必须按实际生效类别检查。无效定义本身被忽略，见第 13 章；有效定义在某个使用点不适用，则仅是那个使用点出错，不撤销定义。

### 10.3 默认作用域

描述写在宿主哪个 subcircuit 定义内部，默认属于该电路层次；随该子电路在各实例上下文中生效。未位于 subcircuit 内的描述属于顶层。

顶层可复用定义默认向下可见；顶层几何或语义实例并不在所有子层重复应用。继承沿实际子电路实例化关系，不根据文件缩进或偶然的文本嵌套判断。

### 10.4 显式路径

**【已确认】** 在入口参数中使用字符串数组指定逐级子电路实例路径：

```text
* @RNL(scope=["XTOP", "XIN"]) #M1 @AT(x=10)
```

`#M1` 和其它局部引用都在 `XTOP/XIN` 的目标层次解析，而不是在该条语句的物理位置解析后再移动图形。

在顶层，路径从根层次开始；在 subcircuit 内，路径相对于其每个实例，且只允许向下。空数组等同未给出。路径段是实例名，不是子电路类型名、文件路径或类型包名。

不提供 `..` 父级操作、根重置、通配符和递归搜索。若宿主允许某实例真的名为 `..`，该字符串只按名字处理，不具有上行意义。

### 10.5 继承与优先级

可复用的类型、符号、资源等定义默认向下继承，允许通过定义操作的 `inherit=false` 限制为本层。语义实例、具体虚元件、note、路径和摆放等不向下继承。

沿具体实例路径解析同名定义，优先级为：当前层次有效定义、最近可继承祖先定义、更远可继承祖先定义、默认标准定义包。同层最后一条有效定义胜出。较晚的父层定义不能以时间顺序压过子层定义。

**【已确认】** 入口中的显式 `scope` 先确定目标层次；定位到同一具体目标层次的语句按统一源顺序参与同层覆盖。显式路径本身没有额外优先权。

### 10.6 多实例路径与局部上下文

同一 subcircuit 的不同实例可以继承不同定义。不能给整个子电路类型固定绑定到某一个父层的定义包。

按原则稿：继承引用在任一实际相关路径下可解析，就不因其它失败路径把整条源描述一概判错；仅部分路径失败时 lint 给出 warning，解释器在失败路径忽略对应描述。所有相关路径均失败时是基本错误。

完整输入以外的片段检查应注明缺少上下文，不能宣称已经验证全部宿主和 RNL 引用。未实例化 subcircuit 的独立 lint 环境仍属需要另行统一的细则，不能凭空假设某个外部库可用。

### 10.7 block symbol 的接口例外

子电路自带的 block symbol 可供父电路渲染该子电路实例使用，这是定义只向下可见的接口例外。它不把子电路内部所有 RNL 名称导出到父层，也不允许父层用本地 `%name` 绕过层次读取内部对象。

父层获得的应是已经解析的接口外观及端口绑定；具体发布语法属于图形／接口操作契约，见附录 C。

## 11. 标准定义包与用户覆盖

### 11.1 标准名没有强制前缀

**【已确认】** 允许直接使用 `$DIFFPAIR`、`$CURRENT_MIRROR` 等标准类型名，不要求 `RNL_`、`rnl.`、`_` 或其他保留前缀。用户可以定义同名对象，按普通覆盖规则取代默认库定义。

此规则作用于库对象名称，不允许用户改变 `@AS` 的词法和参数绑定规则，也不允许创建一个仅大小写不同的第二操作。

### 11.2 默认库的逻辑模型

标准结构在语义上等价于在用户定义之前加载的最低优先级默认定义包。实现可内置这些数据，也可从本地包提供，但必须呈现相同的名称解析行为。

RNL 不要求在宿主网表里加入 `.include` 来加载自己的标准包，不因为出现类型名而自动联网，也不把宿主模型库与 RNL 结构库混为一谈。

### 11.3 解析后的绑定优先于名称特判

看到 `$DIFFPAIR` 后，必须先在当前环境解析有效定义，再进行语义处理。渲染器不能仅按字符串 `DIFFPAIR` 直接分派内置布局，绕过用户覆盖。

可以优化已确认身份的标准定义；不能把这种优化变成按名字强行恢复标准实现。角色所需类型也应以解析后的定义为依据，不只根据名称字符串猜测。

### 11.4 标准演进

旧文件保留自己的有效同名定义时，标准库后来加入同名对象，不应夺走用户绑定。

如果用户删除自有定义而改用标准版本，兼容性仍取决于角色、类型关系和语义契约，不能仅凭同名保证。实现应能够指出所用标准包及版本／来源；其加载和版本锁定语法尚待定义。

### 11.5 组合定义与类型扩充

**【已确认】** 用户可以用已有简单结构组合更大的结构，也应通过类型继承和扩充表达新的结构类型。例如 lowpass filter 是扩充自 filter 的独立类型，而不是在使用 filter 时传入模式参数。

**【已确认】** 同名覆盖只替换该名称对应的定义，不牵连其它已有组合定义的内部组成。例如覆盖 `DIFFPAIR` 不会重新绑定已定义 `DIFFSTAGE` 内部使用的差分对；只有显式修改或重新定义该组合，才改变其组成。对覆盖后的类型进行新的直接引用仍按普通名称规则解析。

**【待定】** 用户类型定义的文本语法、继承和扩充的具体规则、类型兼容性及内部绑定身份的存储方式尚未确定。本稿不发明定义操作、角色变量、模板展开或可执行宏，也不能用实现时的重新绑定绕过上述覆盖边界。

## 12. 核心操作的最小契约

本章使讨论中的 `as`、`at` 和版本声明有明确的参数示范契约，不把整个旧稿词汇表自动升级为已确认标准。`AS(type,id)` 以及本轮确认的 `AT` 逐坐标更新和初始 free 状态均为已确认规则；其它具体字段细则仍标为本稿补全。

### 12.1 `@AS`：解释一组对象为某种结构

```text
主对象列表 @AS(type, id可选)
```

上行是签名说明，不是实际输入；实际省略可选参数，不输入“可选”等字样。

| 字段 | 位置 | 值 | 要求 |
| --- | --- | --- | --- |
| `type` | 1 | `$` 类型引用 | 必填，必须绑定到可用于结构解释的定义 |
| `id` | 2 | 合法 RNL 名称字符串 | 可选；给本条结果命名 |

作用于整个有序主对象列表，不是对每个对象分别创建相同结构。给出 `id` 后创建本层可引用的语义对象，其声明类型记录实际绑定的类型定义；不给出则创建不能按名字引用的匿名描述。

**【已确认】** AS 只接受 type 和 id，不接受类型专属字段或参数。类型定义提供角色、主对象数量及类型约束，不扩充 AS 的参数签名。结构变体应使用通过继承和扩充形成的独立类型。

```text
* @RNL #R1 #C1 @AS($LOWPASS_FILTER, "filter")
```

上述类型名仅为示例，需有效定义存在。`@AS($FILTER, mode="lowpass")` 因未知字段 mode 而失效。用户覆盖类型后，AS 使用有效定义的角色和主对象契约，不强制恢复标准库同名定义，也不强制检查实际电气拓扑。

### 12.2 `@AT`：声明坐标约束

**【已确认】** AT 仅指定对象的 x、y 坐标，不绑定旋转、翻折、缩放或端口朝向。每条声明至少指定一个坐标；x、y 不要求同时出现。

```text
#M1 @AT(1, 2)
#M1 @AT(x=1)
#M1 @AT(y=2)
```

**【本稿补全】** 恰好一个可放置对象，当前支持宿主实例、具体虚元件或 note；不接受端子，也不隐含创建视觉容器。AT 未声明具名主对象角色。

| 字段 | 位置 | 值 | 要求 |
| --- | --- | --- | --- |
| `x` | 1 | 有限数 | 可省略，但 x、y 至少指定一个 |
| `y` | 2 | 有限数 | 可省略，但 x、y 至少指定一个 |

**【已确认】** 每个坐标的初始状态都是 free，表示渲染器可根据高层语义及其它描述决定该坐标。free 是本稿描述的状态，不新增裸值字面量。有效 AT 只更新明确指定的坐标，未指定坐标保留此前状态；若从未指定，则仍为 free。

```text
* @RNL #M1 @AT(x=1)
* @RNL #M1 @AT(y=2)
```

第一条之后 x=1、y=free；第二条之后 x=1、y=2。再写 `@AT(x=3)` 时 y 保持 2，不被重置为 free。仅有第一条时，y 由渲染器决定。

位置参数仍连续绑定：`@AT(1)` 仅指定 x；仅指定 y 使用 `@AT(y=2)`，不能写 `@AT(,2)`。`@AT` 和 `@AT()` 因未提供坐标而无效。未知字段或非法值使整条描述失效，不产生部分更新。

**【本稿补全】** 坐标不接受 null；将已指定坐标显式恢复为 free 的写法尚待讨论。当前不把省略或 null 解释为释放已有约束。

旋转和翻折应由独立操作处理，并考虑端口朝向，其名称、参数和语义留待专门讨论。缩放同样不属于 AT，本版不在此定义其操作。`rotate`、`mirror`、`scale` 作为 AT 字段均为未知字段。

**【本稿补全】** 位置使用目标电路层次的抽象绘图单位，x 向右、y 向下；不是版图物理坐标或电气参数。

### 12.3 `@VERSION`：文件语法版本

**【本稿补全】** 无主对象；一个必填参数 `value`，既可位置提供也可具名提供：

```text
* @RNL @VERSION("0.1-draft.2")
* @RNL @VERSION(value="0.1-draft.2")
```

它描述所在物理文件，所在记录不允许提供入口 `scope`（包括空数组）。不是在两个声明之间切换语法的指令。建议放在首条 RNL 记录处，但不得占用宿主要求的标题首行。

**【已确认】** 同一物理文件中语法和签名合法的版本声明出现不同版本值时是版本冲突，lint 必须报错，不能以后者覆盖来消除冲突。

**【本稿补全】** 相同解码版本字符串的重复声明允许存在。出现冲突时，该文件没有唯一有效声明版本，不自动选择较早、较晚或较新版本；严格解释器可拒绝该文件的 RNL，宽松工具仅能按外部明确指定版本作带冲突诊断的尽力解析，不得声称文件已通过版本验证。版本检查是文件级前置检查，不适用忽略后条后恢复旧版本的普通语句规则。include 文件分别检查，不互相覆盖。无声明的片段必须由调用环境指定解释版本，不默认为某个工具的“最新版”。

`0.1-draft.2` 只标识这份草案，不意味着正式格式版本 `0.1` 已发布。

### 12.4 其它操作

几何关系、显示标签、路径、符号、资源、虚元件、note 和 block symbol 都使用同一 `@操作(参数)` 语法。它们需要自己的字段及基本语义契约，不能仅因能解析为一般调用就被视为已支持。

附录 C 给出从旧稿迁移的接口示意，但不在本轮定死全部 SVG 子集、图形坐标约定或用户组合结构语法。

## 13. 顺序、失效、覆盖与诊断

### 13.1 处理顺序

遵循原则稿：

```text
解析完整宿主和活动输入
    -> 提取带来源和作用域的 RNL 记录
    -> 通用词法、语法及文件版本一致性检查
    -> 入口上下文和操作参数绑定
    -> 收集定义、按完整输入解析前向引用
    -> 按实际实例上下文检查引用及单条基本规则
    -> 忽略错误语句；同层按源顺序累积及覆盖
    -> 得到实现实际检查范围内自洽的描述集合
    -> 渲染
```

该流程的先后是逻辑依赖，不要求实现只能线性单遍。先使用后定义合法；不能因为逐行扫描时尚未遇到目标而判错。

### 13.2 源顺序与跨文件

**【本稿补全】** 以宿主实际采用的 include／library 活动内容顺序为依据，在 include 出现点展开记录。按物理源顺序及同一行内入口的列顺序排列；块记录以其入口位置确定顺序。

不能按目录遍历顺序、文件名排序或对象名排序替代宿主输入顺序。文件被实际包含多次时，依宿主的实际展开处理。不能自行扫描未包含文件以寻找 RNL 定义。

RNL 结构包的加载顺序尚未定义，但默认标准包必须低于用户定义，见第 11 章。需要包加载才能确定绑定时，实现应暴露其配置，不能假装该配置来自文件中不存在的声明。

### 13.3 基本错误与语句原子性

基本错误包括：封装错误、语法错误、未知操作、未知类型或字段、错误的位置参数顺序、重复赋值、非法值、无效引用、角色绑定失败，以及具体定义规定的单条基本语义冲突。

出错语句整体不生效，不保留其中“看起来有效”的一部分，也不覆盖以前的描述。文件版本冲突另按 12.3 节处理，不能以忽略后条消除冲突。

```text
* @RNL #M1 @AT(x=1, y=2)
* @RNL #M1 @AT(x=8, y=9, mystery=7)
```

第二条的未知字段使其整体忽略；第一条的 x、y 都保留。

### 13.4 无效定义与无效使用点

无效定义不覆盖旧的有效同名定义。对一个名称仍存在有效较早或可继承绑定时，可以绑定到它。这不叫“继续使用无效定义”。

但是，一个定义本身有效，只是类别不符合某个使用点时，不能为了该使用点回退。例如有效的同名 note 遮蔽了结构类型，`$name` 应报错，而不是强制查到旧结构。

若确实没有可用目标，依赖它的描述也失效，不论出现先后。不得以删除角色限制、猜测近似名称或使用占位类型的方式把失败引用悄悄变成有效引用。

### 13.5 循环依赖

**【本稿补全】** 对当前通过具体对象相互引用形成的语义包含关系，不能接受需要无限展开的自引用或循环。它是 RNL 依赖问题，不是宿主电气反馈回路；电路反馈本身不因本条受限制。

未来的组合类型是否允许递归、如何限定递归，以及同名候选循环时的完整选择算法，属于待定的定义系统问题。本稿不沿用旧稿未经确认的强连通分量淘汰算法作为既定标准。

### 13.6 覆盖粒度

后出现的有效描述按其操作契约规定的覆盖单位，覆盖同层已存在的冲突信息；覆盖单位以外的未冲突信息保留。层次继承优先于源顺序。

对于本稿的 AT，x、y 是两个独立覆盖槽；后条有效声明只更新明确指定的坐标，另一坐标保留数值或 free 状态。旋转、翻折、缩放、符号外观和显示别名不在其覆盖范围内。对于同名 `as` 结果，本稿采用整个结构定义替换：类型和角色绑定作为整体，不拼接成作者没有声明过的半个旧结构加半个新结构；独立几何属性是否冲突则分别处理。

匿名描述不会仅因操作名或结构类型相同就自动覆盖另一个匿名描述。合法覆盖本身不是基本错误。

实现若从语义生成布局关系，其源顺序应归属于该语义描述，而不是因为渲染较晚执行就自动获得最高优先级。

跨条高层语义冲突、全部几何约束是否可同时满足、以及电气一致性均不要求通用求解。发现冲突时在实现检查的范围内遵循后者优先，不引入坐标永远优先、hard/soft 或必需／可选扩展两套规则。

### 13.7 诊断与保留

lint 将基本错误报告为 error；默认解释器和渲染器静默忽略出错语句并继续处理。文件版本冲突属于 12.3 节的文件级诊断，不采用该语句级恢复方式。部分实例路径可解析的特殊情况按第 10.6 节报告 warning。实现可声明更严格的停止策略，但不应把它说成默认规则。

诊断应定位到物理文件、行列或范围，以及具体记录、字段或引用；块载荷需保留字符到来源的映射。可以附错误码，错误码不创建新的容错类别。

建议编辑器保留未知和错误语句的原始内容与相对顺序，不因 lint 结果自动删除、修复或重写。

## 14. 版本、扩展和保真编辑

### 14.1 三种版本不混淆

语法文档版本、标准定义包版本、宿主语言／仿真器版本是不同维度。支持其中之一不表示支持其它全部组合。

本稿的文档标签可以用于 `@VERSION`，但还没有标准库发布号或商业宿主认证矩阵。示例出现 `$DIFFPAIR` 不构成已经发布某份可下载标准包的声明。

### 14.2 未知内容

操作词法允许名称不等于实现必须支持它。类型引用词法合法也不等于目标定义存在。

不认识的操作、类型、扩展字段和不支持的资源内容，统一按基本错误处理，不采用静默接受未知字段、自动创建类型或未知结构回退为 GROUP 的机制。

不支持的版本声明应由 lint 报错。解释器可按自己明确支持的语法识别独立记录，但不得声明完整支持该文件版本，亦不得把同形文本在新版本的未知语义当作已知事实。严格实现可拒绝整份 RNL 输入。

### 14.3 扩展操作与用户库对象

**【本稿补全】** 操作名词法允许点分限定，例如 `@ACME.ROUTE(...)`，仍按 ASCII 大小写不敏感处理。点只属于操作标识，不触发模块导入或网络访问。核心和扩展都必须有明确操作契约；两个操作不能仅大小写不同。

用户增加结构、符号或虚元件定义，不必为每种结构创建新操作。它们优先作为可引用的库对象通过既有操作使用。扩展操作的名称治理和登记规则待定，不把旧稿的特定扩展前缀强行沿用为已确认规则。

### 14.4 编辑保真

只修改 RNL 时，应保留宿主正文及普通注释的内容、顺序、编码和换行。不得借整理 RNL 之机格式化或重新生成宿主网表。

转换行式和块式时，不能改变操作参数、引用、必需空格、角色标注紧邻关系或描述顺序。对象重命名须作为显式编辑，不能仅因显示别名而改宿主名。

不保证图形往返一致，也不要求编辑器把所有输入改为同一种排版。推荐规范写法是输出习惯，不是缩减合法语法。

## 15. 形式语法

### 15.1 记法与分层

本章使用 EBNF 风格：`[ ... ]` 为可选，`{ ... }` 为重复，`|` 为选择；引号内为字面字符。`ci("rnl")` 表示仅 ASCII 大小写不敏感的固定单词。`? ... ?` 为正文定义的词法终结符或上下文约束。

这里不把任意宿主注释语言重新写成一种统一文法。宿主适配器先提供有来源映射的注释字符及边界；第 3 章的安全空格、硬边界、入口状态和恢复规则是文法的一部分，不是可省略建议。

### 15.2 封装

```ebnf
rnl-record       = line-record | block-record ;
rnl-tag          = "@", ci("rnl") ;
rnl-header       = rnl-tag, [ header-arguments ] ;
header-arguments = "(", hws, [ header-named-list ], hws, ")" ;
header-named-list = header-argument, { hws, ",", hws, header-argument } ;
header-argument  = parameter-name, hws, "=", hws, header-value ;
header-value     = ? 不含物理换行的 value；scope 契约要求字符串数组 ? ;
line-record      = rnl-header, hws1, line-statement, line-boundary ;
block-record     = rnl-header, hws, "{", statement, "}" ;

hws              = { " " | TAB } ;
hws1             = ( " " | TAB ), hws ;
line-statement   = ? 不含物理换行的 statement ? ;
line-boundary    = ? 当前物理行末或宿主注释末，取较早者 ? ;
```

选择规则：入口头部结束后，在同一物理行越过水平空白首先为 `{` 时取块式；不得先按行式吞入 `{`。每个 `rnl-tag` 紧前须有一个实际 ASCII 空格，但该空格属于外层宿主注释上下文，不在以上产生式中重复消费。

### 15.3 描述与调用

```ebnf
statement        = aux, { subject, aux }, operation-call, aux ;
subject          = subject-ref, [ role-annotation ] ;
subject-ref      = host-ref | net-ref | rnl-object-ref ;
role-annotation  = "(", ws, name, ws, ")" ;

operation-call   = "@", operation-name, [ argument-area ] ;
argument-area    = "(", ws, [ arguments ], ws, ")" ;
operation-name   = identifier, { ".", identifier } ;

arguments        = positional-list, [ ws, ",", ws, named-list ]
                 | named-list ;
positional-list  = value, { ws, ",", ws, value } ;
named-list       = named-argument, { ws, ",", ws, named-argument } ;
named-argument   = parameter-name, ws, "=", ws, value ;
parameter-name   = identifier ;
```

每个操作的 `@` 紧前也须为实际 ASCII 空格。该空格通常由前面的 `aux` 保存；若操作正好是行式载荷的第一个字符，也可由入口后的实际分隔空格提供。检查依据是保留来源的注释字符流，不要求凭空增加第二个空格。类型引用不是本版主对象；它用于操作参数值。操作名最长匹配后，紧接 `(` 必须解析参数区；仅隔空白后出现 `(` 是语法错误；其余情况按零参数调用处理。不能通过选择省略参数区来回避损坏的括号内容。

具名参数通过未加引号的标识及其后的 `=` 识别；普通裸标识不是 value。参数数量、重复赋值、未知参数及字段类型由签名规则检查。

### 15.4 引用

```ebnf
reference        = host-ref | net-ref | rnl-object-ref | type-ref ;

host-ref         = "#", name, [ ":", host-pin-key ]
                 | "#", ":", host-pin-key ;
net-ref          = "&", name ;

rnl-object-ref   = "%", name, [ ":", name ] ;
type-ref         = "$", name ;

host-pin-key     = positive-integer | identifier | string ;
name             = simple-name | string ;
simple-name      = name-char, { name-char } ;
name-char        = letter | digit | "_" ;
identifier       = ( letter | "_" ), { letter | digit | "_" } ;
positive-integer = digit-nonzero, { digit } ;
```

前缀、名称和选择器之间无空白。主对象位置允许在完整引用后紧邻追加一个 `role-annotation`，端子选择器之后也可标注角色。参数值使用 `reference`，不接受角色后缀。全标注或全省略及角色契约须另行检查。

`%name` 后的数字端子选择器按名称解释；`#` 的未加引号正整数按索引解释。空字符串在 name 位置无效，即使它在一般字符串值位置合法。

### 15.5 值、数组与映射

```ebnf
value            = string | number | boolean | null-value
                 | array | map | reference ;
boolean          = "true" | "false" ;
null-value       = "null" ;

array            = "[", ws, [ value, { ws, ",", ws, value } ], ws, "]" ;
map              = "{", ws, [ member, { ws, ",", ws, member } ], ws, "}" ;
member           = string, ws, ":", ws, value ;
```

映射键解码后必须唯一。`true`、`false`、`null` 只接受小写，不应用操作的大小写归一规则。

### 15.6 字符串、数字和辅助字符

```ebnf
string           = DQUOTE, { unescaped | escape }, DQUOTE ;
escape           = "\\", ( DQUOTE | "\\" | "/" | "b" | "f"
                         | "n" | "r" | "t" | "u", hex, hex, hex, hex ) ;
unescaped        = ? 除 DQUOTE、反斜杠、U+0000..U+001F 之外的 Unicode 标量值 ? ;

number           = [ "+" | "-" ], mantissa, [ exp ] ;
mantissa         = digits, [ ".", { digit } ] | ".", digits ;
digits           = digit, { digit } ;
exp              = ( "e" | "E" ), [ "+" | "-" ], digit, { digit } ;

aux              = { aux-char } ;
aux-char         = letter | digit | " " | TAB | LF | aux-punctuation ;
aux-punctuation  = "." | "," | ";" | ":" | "!" | "?" | "'"
                 | "-" | "_" | "/" | "+" | "*" | "<" | ">" | "|"
                 | "(" | ")" | "[" | "]" | "=" | DQUOTE | "\\" ;

ws               = { " " | TAB | LF } ;
letter           = ? ASCII A..Z 或 a..z ? ;
digit            = "0" | digit-nonzero ;
digit-nonzero    = "1" | "2" | "3" | "4" | "5" | "6" | "7" | "8" | "9" ;
hex              = digit | "A" | "B" | "C" | "D" | "E" | "F"
                         | "a" | "b" | "c" | "d" | "e" | "f" ;
DQUOTE           = ? U+0022 ? ;
TAB              = ? U+0009 ? ;
LF               = ? U+000A，来自合法块载荷的换行 ? ;
```

上式中反斜杠字面采用 `"\\"` 表示一个反斜杠；它是 EBNF 展示约定，不是在实际 RNL 中要求两次转义。Unicode 转义的代理对合法性还须按第 8.3 节检查。

### 15.7 词法优先和文法之外的必要检查

1. 宿主注释结束边界优先于所有 RNL 状态。
2. 合法参数字符串或引号名称内部不识别正式标记和括号；辅助双引号和反斜杠不启动字符串或转义状态。
3. 名称按最长匹配读取；前缀后的文字不按辅助字符拆散。
4. 紧邻完整主对象引用的 `(` 只按角色标注解析，不回退为操作参数或辅助文字。
5. 操作名后紧接的 `(` 开始参数区；仅隔空白后出现 `(` 是错误，不把非法内容解释成辅助文字；已结束调用后的括注可以是辅助文字。
6. 块外层与映射大括号按嵌套配对；本版不接受嵌套操作值或语句块。
7. 一条记录恰好一个操作；`@RNL` 是入口标记，不是可以调用的普通操作名。
8. 名称非空、绑定存在、参数签名、类型关系和单条基本合法性不是单靠 EBNF 能验证的内容。

不能以“EBNF 能接受”替代完整基本 lint，也不能以尚无渲染器否定一条词法和引用均成立的纯语义描述。

## 16. 有效与无效文本对照

下表区分语法与基本语义。合法项仍以必要的引用和操作契约存在为前提；说明性文字不参与解释。

| 输入片段 | 结果／原因 |
| --- | --- |
| ` @AS($DIFFPAIR)` 与 ` @as($DIFFPAIR)` | 操作名等价 |
| ` @AS($diffpair)` | 类型名保留大小写；不自动等于 `$DIFFPAIR` |
| ` @AS($DIFFPAIR, "p")` | 位置 type、id |
| ` @AS($DIFFPAIR, id="p")` | 连续位置前缀后具名补充 |
| ` @AS(id="p", type=$DIFFPAIR)` | 全具名，顺序不限 |
| ` @AS("p", type=$DIFFPAIR)` | 错误位置绑定并重复指定 type |
| ` @AS(id="p", $DIFFPAIR)` | 具名之后出现位置参数 |
| ` @AS($DIFFPAIR, id=p)` | p 不是带引号字符串或其它合法值 |
| ` @AS($DIFFPAIR, %p)` | id 预期名称字符串，不能用对象引用 |
| ` @AT(1, 2) note 3` | 正式值为 1、2；3 为辅助数字 |
| ` @AT 1 2` | 零参数调用加辅助文字；未指定任何坐标，无效 |
| ` @OP` 与 ` @OP()` | 同为零参数调用；有效性取决于操作契约 |
| ` @AS` | 语法合法，但缺少必填 type，基本语义错误 |
| ` @AT()` | 通用语法合法，但未指定任何坐标，无效 |
| ` @AT(y=2)` | 仅更新 y，x 保留此前状态或初始 free |
| ` @AT(x=1)` | 仅更新 x，y 保留此前状态或初始 free |
| ` @AT(rotate=90)` | 未知字段 rotate，整条无效 |
| ` @AT(null, 2)` | x 不接受 null |
| ` @AT(1, 2, mirror=null)` | 未知字段 mirror，整条无效 |
| ` @AT(1, y=2)` | 连续位置前缀加具名 y，合法 |
| ` @AT(1, 2)` | 同时更新 x、y，不影响姿态 |
| ` @AT (1, 2)` | 参数左括号未紧邻操作名，语法错误 |
| `#M1, #M2 @AS($DIFFPAIR)` | 两个主对象，逗号为辅助标点 |
| ` @AT(,2)` | 参数缺项 |
| ` @AT(1, 2,)` | 禁止尾随逗号 |
| ` @AT(01, 2)` | 合法，01 是十进制 1 |
| ` @AT(+1, .5)`、` @AT(1., 02)` | 合法十进制写法 |
| ` @AT(1 2)` | 缺少参数分隔逗号 |
| ` @AT(x=1, x=2)` | 重复参数，不按后者覆盖 |
| `%p (input)` | 未标注角色的主对象 p，加辅助括注；不绑定 input 角色 |
| `%p(input)` | 主对象 p 绑定到 input 角色，需契约支持 |
| `#M1:1(source)` | 完整端子引用后标注 source 角色 |
| `#M1(in_p) #M2 @AS($DIFFPAIR)` | 混合标注和未标注主对象，不合法 |
| `#M1(in_p) #M2(in_p) @AS($DIFFPAIR)` | 若 in_p 为单对象角色，则重复绑定错误 |
| `#M1(unknown) @AT(1, 2)` | 未声明角色错误；at 本稿未定义具名角色 |
| ` @OP(target=#M1(input))` | 参数值引用不接受角色标注 |
| `#M1(in_p)(other)` | 不允许链式角色标注 |
| `$DIFFPAIR$` | 多余尾部 `$`，不是本版类型引用 |
| `%symbol:shape` | 不表示“symbol 命名空间的 shape”；按端子引用解析且需相应对象 |
| `#M1:1` | 第一宿主端子 |
| `#M1:0` | 非法索引 |
| `#M1:"0"` | 引用真实名称为 0 的宿主端子 |
| `&01` | 网络名 01，不是整数 1 |
| `#"M1<0>"` | 特殊宿主名通过引号引用 |
| `#M1@AT(1, 2)` | 操作 `@` 前缺少 ASCII 空格 |
| `#M1 @AT(1, 2) #M2` | 操作后不允许新增主对象 |
| `#M1 @AT(1, 2) (note)` | 合法辅助括注 |
| `#M1 @AT(1, 2) [reviewed] gain=10 "note" C:\tmp` | 均为合法辅助文字，不解释数组、赋值、字符串或转义 |
| `#M1(in_p=1) @AT(1, 2)` | 已进入角色标注，非法角色内容不能降格为辅助文字 |
| `#M1 @AT(x=)` | 已进入参数区，缺少值，不能降格为辅助文字 |
| `#M1 @AT(1, 2) " @AT(3, 4)"` | 辅助引号不隐藏第二个操作，整条记录非法 |

入口参数与作用域对照：

```text
* @RNL(scope = ["XTOP", "XIN"]) #M1 @AT(x=1)
* @RNL(scope=["XTOP", "XIN"]){
*     #M1 @AT(y=2)
* }
```

两条都作用于同一目标实例中的 M1，分别更新其 x、y。下一条没有 scope 的记录仍在其物理所在的默认层次解释。

| 输入 | 结果／原因 |
| --- | --- |
| `@RNL() #M1 @AT(1)` | 空入口参数区，采用默认上下文 |
| `@RNL(scope=[]) #M1 @AT(1)` | 空路径等同默认上下文 |
| `@RNL (scope=["X1"]) #M1 @AT(1)` | 入口参数左括号未紧邻 |
| `@RNL(scope="X1") #M1 @AT(1)` | scope 需要字符串数组 |
| `@RNL(scope=["X1"], scope=["X2"]) #M1 @AT(1)` | 重复入口参数 |
| `@RNL(other=1) #M1 @AT(1)` | 未知入口参数 |
| `@RNL #M1 @AT(1, scope=["X1"])` | scope 不属于 AT 参数 |
| `@RNL @AS($FILTER, mode="lowpass")` | AS 不接受类型专属参数 |

上述片段嵌入宿主注释时，入口前仍需 ASCII 空格。同一文件若同时声明 `@VERSION("0.1-draft.2")` 与 `@VERSION("0.1-draft.3")`，即为版本冲突，不能以后者覆盖；此处第二个字符串只用于冲突示例，不表示该版本已发布。

封装对照：

```text
* @RNL #M1 @AT(1, 2)
```

合法行式。

```text
* @RNL{
*     #M1 @AT(1, 2)
* }
```

合法块式；增加大括号不改变作用域。

```text
* @RNL #M1 @AT(
*     1, 2)
```

第一条行式在行末失效，第二行不会自动继续它。

```text
* @RNL{ #M1 @AT(1, 2) #M2 @AT(3, 4) }
```

块内两次操作，整条记录非法。

```text
*@RNL #M1 @AT(1, 2)
```

不是符合本稿安全绑定的输出；不能把它作为可移植普通注释。

## 17. 规范生成风格与检查清单

### 17.1 推荐生成风格

**【已确认】** 推荐入口与操作关键字统一使用大写，例如 `@RNL`、`@AS`、`@AT`，以便在辅助文字中识别；解析仍不区分 ASCII 大小写。参数名、角色名及布尔值不随关键字改成大写；标准类型采用其实际名称；不要因此改变自定义类型名。短描述用行式，需要换行用块式。括号内逗号后留空格，`=` 两侧不加空格，操作名紧贴左括号。操作前总有 ASCII 空格。

```text
* @RNL #M1 and #M2 @AS($DIFFPAIR, id="input_pair")
```

零参数操作可省略 `()`；有参数时保留参数区。角色不对称时建议给全部主对象显式标注角色；角色名必须来自有效契约。位置参数适合少量显然的值；参数较多时优先具名。这只是推荐，不宣称某一种风格已经通过 LLM 生成可靠性对比测试。

不要为减少字符数删掉宿主 `*` 后的空格，不要拆分字符串和转义，不要为了对齐改变角色标注的紧邻关系。

### 17.2 语法符合性检查范围

语法实现至少应覆盖：行式和块式边界、入口参数、参数括号紧邻性、宽松十进制数、必需空格、操作大小写、引用和引号名称、角色标注及零参数调用、位置与具名参数混合、递归数组映射、放宽辅助标点后的上下文优先级、辅助引号不屏蔽标记、未知正式标记及局部错误恢复。

完整解释还需要：宿主对象解析、操作契约、类型定义环境、作用域、继承、多实例路径、前向引用、逐坐标覆盖及文件版本冲突。只做通用语法检查的工具不得宣称已经验证电路或标准结构。

### 17.3 本次文档状态

本次交付为 Markdown 规范文本，不附完整解析器、渲染器或全套网表样例。文档中的正反例是规则示意，不是宣称已经运行的自动化兼容性测试结果。

未执行 SPICE、HSPICE、Eldo、Spectre 等仿真器实测；本稿也没有认证任何商业工具组合。外部资料核验只用于保守注释绑定和基础字面量设计。

## 18. 本稿明确不定义的内容

以下事项保持开放，不能根据本稿示例自行推断为已发布契约：

1. 用户组合结构与类型继承的定义语法、角色变量、模板展开、递归和类型兼容关系。
2. 标准包物理格式、导入操作、包版本锁定和满足覆盖隔离的内部绑定实现。
3. 完整标准结构及虚元件词汇表、各结构的布局实现。
4. 全部几何关系、独立的旋转／翻折及端口朝向操作、坐标释放、线条级符号格式、静态 SVG 子集、资源路径和摘要策略。
5. 未实例化 subcircuit 的统一 lint 环境、复杂同名候选依赖循环的最终算法。
6. 多视图、视觉容器、语句嵌套、块级默认属性和控制流；当前外层大括号没有这些含义。
7. 商用宿主逐版本及逐入口的兼容性认证。

本稿的通用语法可以独立于这些模块被解析和评审。后续模块必须在明确版本和契约下增加能力，不得让旧的辅助文字突然变成参数，或让既有外层大括号悄悄创建新作用域。

| 旧稿／中间讨论形式 | 本稿形式或处理 |

## 附录 C. 既有功能如何使用统一语法

### C.1 结构词汇迁移方向

以下名字来自前序讨论和旧稿，用于表明“结构是类型定义而非操作关键词”。它们是候选默认库词汇，不是本稿已交付的结构包。主对象角色及基本限制仍需各定义公开提供。

| 类别 | 候选类型引用 |
| --- | --- |
| 结构组合 | `$GROUP`、`$DIFFPAIR`、`$DIFFSTAGE` |
| 常见电路 | `$RC_FILTER`、`$COMMON_SOURCE`、`$CURRENT_MIRROR` |
| 拓扑／设计意图 | `$CROSS_COUPLED`、`$MATCH`、`$BIAS` |

例如：

```text
* @RNL #M1 #M2 @AS($DIFFPAIR, "pair")
* @RNL %pair(input) #ITAIL(tail) @AS($DIFFSTAGE, "stage")
```

这里结构嵌套通过命名对象引用表达，不是嵌套操作或嵌套 RNL 大括号。`input`、`tail` 是示例类型契约中的角色名，最终标准角色仍由相应定义发布。

### C.2 绘图及资源操作的接口候选

下列形式沿用旧稿的功能意图，仅示范如何装入当前语法。没有本稿第 12 章或已声明操作模块的完整契约时，不据此宣称 lint 已能接受其全部字段。

```text
* @RNL #M1 @ALIAS(text="Input device")
* @RNL #M1:1 @PINPOS(x=-2, y=0)
* @RNL #M1 #M2 @SYMMETRY(axis="vertical", at=10)
```

```text
* @RNL{
*     @SYMBOL(
*         id="sym_amp",
*         anchors={"inp":[0,2], "out":[8,4]},
*         resource=%amp_art,
*         inherit=true
*     )
* }
```

```text
* @RNL{
*     #X1 @APPEAR(
*         symbol=%sym_amp,
*         bind={"inp":#X1:1, "out":#X1:2}
*     )
* }
```

```text
* @RNL @VIRTUAL(id="g0", type=$GROUND, net=&0)
* @RNL %g0 @AT(0, 10)
* @RNL @NOTE(id="caption", text="Input stage")
* @RNL @WIRE(net=&out, paths=[[#M1:1, [10,0], #M2:1]])
```

`GROUND` 同其它类型一样是可覆盖的库对象，不是宿主地节点的第二份定义。路径网络关联、锚点绑定和几何坐标仍相互独立；上例不要求端子的实际网络必须为 `out`。

符号与资源分别引用 `%sym_amp`、`%amp_art`，名字已经统一，不重新引入 symbol/resource 名称空间。SVG 或其它精细线条数据可放在字符串／资源值中；安全子集和资源管理需后续模块规定。

**暂存日期：2026-09-21。** 本附录保存讨论进度，不宣布新操作可用，也不扩展第 15 章的有效语法。候选之间可能相互替代，不能组合成一套已经确定的实现要求。正文的历史决策保留作对照；特别是 AS、对象前置、类型初始化和名称覆盖，不作为后续探索不可改变的前提。

### E.1 首个案例与目标

先使用单层的 [current-mirror-loaded-differential-pair.icproj.json](../../apps/editor/src/examples/current-mirror-loaded-differential-pair.icproj.json)，暂不从有层次的 OTA 开始。

探索目标是找出导出宿主网表及附加描述、再导入后接近原图所需的信息。精细视觉重现是一个能力验证案例，不自动改成所有 RNL 输入必须保证视觉往返一致；仅含语义、没有完整坐标的描述仍应有价值。尚未实现或运行该案例的 RNL 往返验证。

优先讨论五项能力：走线路径及风格、虚器件、命名与临时对象、通过端子相对位置确定器件姿态、对象间对齐／对称／居中等关系。

### E.2 WIRE 的基础候选

用户认可走线应区分多个风格维度；以下字段和值是助手提出的简化候选，未最终确定：

| 字段 | 候选值 | 职责 |
| --- | --- | --- |
| line | solid、dashed | 线条外观 |
| route | auto、straight、orthogonal、hfirst、vfirst | 相邻路径锚点间的连接方式 |

候选写法：

```text
#M1:d %p1 %p2 #M2:d @WIRE(line="solid", route="orthogonal")
```

对象顺序表示路径经过顺序。助手建议至少两个锚点，锚点为必须经过的位置；straight 直接相连，orthogonal 为正交折线，hfirst／vfirst 为两种顺序的直角连接，同轴时退化为直线。缺省 solid／auto、飞线是否仅需 straight 加线型、逐段属性及覆盖单位仍待确认。语法示例以前缀引用及端子名称确实可解析为前提。

路径只描述视觉，不创建宿主连接，也不要求以电气一致性校验作为合法性前提。端点及中间点可以来自宿主端子、虚器件显示端子或几何点。

### E.3 Symbol 端子方向与位置关系

用户明确的设计方向：每个 Symbol 端子拥有局部位置及可选的出线方向；方向由 Symbol 定义，也可以无方向。RNL 描述端子应处于器件左侧等相对位置，渲染器据此选择器件姿态，端子位置和方向随 Symbol 一起变换，不独立拉动 Symbol 内端子。

出线方向仅供路由优化：auto／orthogonal 可参考，straight 不受其限制，不能把逆向出线自动视为错误。当前不引入独立 FACING 操作。

对齐、居中、位置对称应明确作用于哪个参考点或端子；位置对称与 Symbol 镜像不是同一个概念。以下仅示意可能的表面表达：

```text
#M1:g #M1 @LEFT
#M1:d #M1 @ABOVE
```

LEFT／ABOVE 尚无最终签名、距离、参考点或冲突处理契约。底层是否统一采用绝对坐标与相对位置约束、如何处理多个可行姿态，需通过案例与求解原型验证，不提前承诺所有未来约束均可归约为位置关系。

### E.4 虚器件与点

需要创建接地、VDD、端口等视觉对象，并将其显示端子关联至既有宿主网络或接口；创建视觉对象不创建电气器件或网络。同一宿主网络可以有多个显示对象。

用户确定点类型的正式名称为 `$point`。类型名区分大小写；先前临时使用的 `$P` 不作为最终名称。点的命名创建、初始化和匿名写法仍待定。

标准名或内部类型能否被覆盖重新保持开放。应区分语言基础能力、类型定义身份和名称遮蔽；如果允许遮蔽，是否需要显式访问原定义的方式也需讨论。本附录不将任何限定名或不可覆盖标记提前加入语言。

### E.5 对象模型与初始化候选

已讨论的模型方向：point 为几何对象，diffpair 为持有成员及角色引用的关系对象。两者可以同为 RNL 对象类型，但不因此拥有相同能力；diffpair 不自动具有坐标、端子或视觉容器。用独立关系对象承载差分对，比在两个器件上分别添加无身份标记更便于组合、引用和诊断。该方向得到用户基本认可，最终类型体系与声明方式未定。

参数需要区分：对象实例的初始状态、成员引用、改变结构身份的类型变体，以及宿主电气参数。通用语法是否允许初始化参数，不应仅由“DIFFPAIR 通常不需要配置参数”推出禁止。正文 AS(type,id) 仍是现有契约，是否扩展或替换需要独立决定；lowpass 等结构变体采用独立扩充类型的方向不自动禁止点坐标等实例初始化数据。

以下保存先后提出的替代方案，不要求同时支持：

| 候选 | 目的及未决问题 |
| --- | --- |
| `%$point(1,2)` | 有类型的匿名对象初始化；通用构造参数及其它类型如何绑定成员尚待定义 |
| `@AS($point,"p")` 后接 `%p @AT(1,2)` | 复用声明与属性操作；用户指出零主对象 AS 不够自然，不作为已接受方案 |
| `%$point(1,2) @NAME("p")` | 独立命名操作；是否允许已有对象别名、重绑定及与 AS 的双重命名入口未解决 |
| `(1,2) @AS($point,"p")` | 接近“坐标 as point p”的阅读顺序；裸括号与辅助文字冲突 |
| `%(1,2) @AS($point,"p")` | 以明确前缀引导初始化数据；这是最新候选，不是确认方案，%() 不预设为点 |
| `#M1 #M2 @AS($DIFFPAIR,"pair")` | 现有关系声明；是否保留 AS 以及对象前置应与其它路线共同检验 |

声明对象和引用不等于脚本执行。探索仍坚持纯数据：不执行用户构造函数、任意代码、网络访问或表达式求值。若借用 Python 做研究原型，Python 是开发者验证语义的工具，不成为网表中的可执行载荷。

### E.6 下一条探索路线（提议，未实施）

用户提出先暂停围绕现有分隔符和 AS 形式局部优化，从多个实际原理图的简洁自然语言描述提炼共同语义；必要时用临时 Python 表达及渲染／求解器跑通案例，再决定 RNL 表面语法。
